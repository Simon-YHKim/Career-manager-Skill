# reference/jd-browsing.md — JD Browsing (내장 웹 리서치 모듈)

> 스킬 **내장·자체완결** 런타임 웹 리서치 모듈. 구 'insane-search' 개념을 **우리 스킬로 클론·내장**
> (외부 스킬 의존 없음). 취업 관련 시의성 데이터를 요청 시점에 공개 웹에서 수집:
> **공고 발굴(JD Discovery)** + 기업·연봉·인재상·JD 원문·직무 트렌드.
> SKILL §4·§6(①③④⑥⑦)·portfolio-builder P0·P3이 참조. Durable 규칙은 `methodology.md`, 여기선 시의성만.

## 0. 원칙 (safety-first)
- **공개 콘텐츠만.** 로그인·페이월 **우회 금지**. **자격증명 저장·전송 금지.**
- **날조 금지.** 실제 검색 결과만. 못 찾으면 '데이터 확보 실패' 명시 + 사용자에 요청.
- **요청일 기준 최신.** 모든 항목에 **출처 + 조회일 + Truth Tier**(S 공식/원천 · A 정부·메이저 · B 커뮤니티 주의 · C 추론·미확인).
- **Phase 0→3**: 0 정의·키워드 → 1 공개 검색 → 2 교차검증 → 3 종합.
- **자유도 보존 (배제 금지 — 최우선):** 스코프·정밀도 향상은 **더 많이 찾기 위한 것**이지 가능성을 없애는 게 아니다. 확장(더 많은 쿼리·도메인·인접 직무)은 하되 **하드 필터로 공고를 자동 배제하지 않는다.** 낮은 적합도도 **목록에 남겨** 점수·순위로 정렬만 하고, **거르는 건 사용자 선택**(필터)에 맡긴다. "모든 직업에 대한 가능성"을 시스템이 임의로 닫지 않는다.

## 1. 취득 실패 처리 (게이트·차단·미렌더·오조준) — 정지하되 버리지 않는다
채용공고는 **불특정 다수 대상**이라 상세가 막혀도 공개 신호는 대개 존재한다. 다만 **실패 유형마다 대응이 다르다** — 전부 "게이트"로 뭉뚱그리면 되찾을 수 있는 것도 포기하게 된다.

**(1) 실패 유형 판별 (증상 → 유형 → 대응)**
| 증상 | 유형 | 원인 | 1차 대응 |
|---|---|---|---|
| 로그인 폼·"회원만 열람" | **G 게이트** | 로그인·페이월 | **우회 금지** → (2) 폴백 사다리 |
| HTTP 401 / **403** / 407 / 429 | **B 차단** | 봇 차단·레이트리밋·지역 | **우회 금지**(UA 위장·프록시 회피 금지) → 다른 진입점 1회만 재시도 → (2) |
| 200인데 본문이 껍데기·목록 0건 | **R 미렌더** | **JS SPA** (자사 채용홈 다수) | (2) — 특히 애그리게이터·모바일 도메인 |
| 200인데 개별 공고가 아닌 **색인·검색 페이지** | **M 오조준** | 쿼리가 카테고리 페이지에 히트 | (3) 쿼리 교정 |
| 404 · "마감"·"모집 종료" | **X 만료** | 공고 종료 | §2 (2-c) 신선도 게이트로 |

**(2) 폴백 사다리** — 위에서부터 시도, **성공하면 즉시 중단**(비용 절약)

> ⚠️ **웹 페이지를 마크다운으로 변환해 주는 도구 하나만 쓰고 "본문 없음"으로 끝내지 않는다.** 그 도구는 최종 렌더 화면을 못 보기 때문에 SPA에서 **항상 빈 껍데기**를 돌려준다. 아래 3번이 이 경우의 정답이고, 실측상 **가장 수율이 높다.**

1. **다른 보드 교차** — 같은 공고가 여러 보드에 중복 게재된다. 원티드 403이면 잡코리아·사람인·인크루트·Indeed에서 같은 회사×직무를 찾는다.
2. **모바일·대체 도메인** — `m.` 서브도메인이 서버렌더인 경우가 많다(예: `m.saramin.co.kr`).
3. **[R 미렌더 핵심] 데이터 경로 직접 조회** — **SPA는 화면만 비어 있을 뿐 데이터는 공개 API로 온다.** 브라우저가 보내는 것과 동일한 요청을 재현한다.
   1. 원본 HTML을 받아(`curl -sSL -A "<일반 브라우저 UA>"`) `<script src=...>` **번들 목록**을 확보한다.
   2. 번들을 받아 **엔드포인트 문자열**을 뽑는다 — `/api/`, `.data`, `.json`, `.php`, `.cmd`, `.do`, `ajax`, `fetch(`, `url:`.
   3. **호출 방식과 파라미터 키까지** 번들에서 확인한다. GET 쿼리인지 **POST form-urlencoded**인지, 키 이름이 무엇인지(`page`/`p`, `keyword`/`fText` 등). 파라미터를 추측하면 500이 난다 — **번들에 적힌 이름을 그대로 쓴다.**
   4. 요청 시 `Referer`(해당 사이트)와 일반 브라우저 UA를 붙인다. 응답이 JSON이면 파싱, HTML 조각이면 그대로 파싱한다.
   - ⚠️ **경계 — 이건 우회가 아니다.** 로그인 없이 공개된 데이터를, 그 사이트가 공개해 둔 정식 경로로 읽는 것이다. 다만 응답이 **401/403이거나 인증 토큰·세션을 요구하면 거기서 멈춘다**(→ G 게이트). **로그인을 흉내 내지 않고, 인증을 우회하지 않으며, 레이트리밋을 회피하지 않는다.**
4. **검색엔진 스니펫·캐시** — 제목·요약·마감일이 스니펫에 노출되는 경우.
5. **회사 공식 경로** — 채용 보도자료·IR·채용 브랜딩 기사(Tier A).
6. 전부 실패 → **`[상세 미확인 — 직접 접속 확인]`** + **실패 유형 코드**를 기록하고 다음 공고로 넘어간다.

> 실측(2026-07): `samsungcareers.com`을 "JS SPA라 본문 없음"으로 처리해 포기했으나, 실제로는 목록이 `POST /hr/list.data`(form-urlencoded, 키 `currentPageNo`·`strTxt`·`strKey` 등), 상세가 `GET /recruit/detail.data?seqno=…`로 **로그인 없이 전문 공개**돼 있었다. 마감일·자격요건·전형일정·첨부파일까지 전부 회수 가능했다. **3번을 안 밟은 것이 유일한 실패 원인이었다.**

**(2-b) 상세를 받았으면 끝이 아니다 — 부속 데이터 회수 (미회수 시 채점 불가)**
- **첨부파일 목록을 반드시 확인한다.** 상세 응답의 `addFiles`·`첨부`·`download` 필드에 **상세 요강·직무기술서·입사지원서 양식**이 들어 있다. 파일 경로는 대개 `<호스트>/<자산경로><filePath><fileName>` 형태로 조립된다. 받은 뒤 §1-(5)의 PDF/문서 추출 사다리를 적용한다.
- **직무 목록이 별도 사이트로 분리된 경우를 따라간다.** "직무별 상세는 ○○ 홈페이지 참조" 같은 안내가 있으면 그 링크가 곧 **적합도 채점의 근거**다. 따라가지 않으면 `직무 미확인`으로 남아 확신도가 '낮음'에 고정되고, 승격 가드에 막혀 좋은 공고가 묻힌다.
- 그 직무기술서 사이트도 SPA면 다시 **3번**을 적용한다(중첩 적용).

> 실측(2026-07): 삼성전자 DS 공고 본문엔 직무 목록이 없고 `samsung-dsrecruit.com`으로 넘긴다. 그 사이트의 `POST /set/jdLoad.php`(키 `p`·`fText`·`fDuty`·`fDivision`·`fArea`·`fOrder`)를 호출하니 **직무기술서 82건**의 담당업무·필수역량·우대역량 전문이 나왔다.

**(3) 쿼리 교정 (M 오조준)**
- **색인 URL 패턴은 채점 대상이 아니라 목록 수확용**이다: `/job-category`, `/jobs/list`, `/job-industry/`, `/Search/?`, `/starter/`. 여기서 **개별 공고를 추출**해 채점한다. 색인 페이지 자체를 공고로 올리지 않는다.
- 검색어에 **연·월을 넣지 않는다**("2026년 7월") — 연월 키워드는 색인·기획 페이지를 상위로 끌어올리고 **만료 공고**를 부른다.
- 보드 검색 URL에 **필터 파라미터를 직접 실어** 서버렌더 결과를 받는다(예: 경력 구간·지역 코드). 검색 UI를 흉내 내는 것이 아니라 **공개 쿼리스트링**을 쓰는 것이다.

**(4) 기록 의무 + 점수 반영 (허위 정밀도 차단)**
- 실패한 URL은 **전부** 발굴 보드 상단 `GATED`에 `URL — 유형코드(사유)` 형식으로 남긴다. **조용히 빠뜨리지 않는다.**
- 취득 수준이 **오차 폭과 확신도를 결정**한다(evaluation §5.9-(2)와 동일 규율):

| 취득 수준 | 오차 | 확신도 |
|---|---|---|
| 공개 상세 원문 확보 | ±5 | 높음 |
| 폴백 1–3단으로 요건·마감 확보 | ±10 | 중간 |
| 제목·회사만(폴백 전부 실패) | **±15–20** | **낮음(고정)** |

- **승격 가드:** 확신 '낮음' 공고는 점수가 높아도 **`최우선`으로 올리지 않는다**(evaluation §5.8-b). `[확인 필요]`로 두고, 사용자가 원문을 확인해 확신이 올라가면 승격한다. **배제가 아니라 보류다** — 목록에는 그대로 남는다(자유도 보존).
- 추론 결과는 Truth Tier로 등급화(추론 = B/C), **확정 아님** 명시. 사용자 확인 시 [T1] 승격.

> 실패 사례(학습, 2026-07 실사용): `wanted.co.kr` **403(B)**, `samsungcareers.com`·`careers.lg.com` **JS 미렌더(R)**, 사람인 검색결과 **서버 미노출(R)**, 잡코리아 "생산기술 취업" **색인 페이지(M)** 가 결과로 반환. 당시엔 전부 "게이트"로 처리해 폴백을 시도하지 않았다 — 위 사다리로 방지.

**(5) 첨부파일·외부 링크 JD (PDF·공고문서·별도 채용페이지)**
공고 본문이 짧고 **"상세 요강은 첨부 PDF 참조"·"자세한 내용은 링크"** 로 넘기는 경우가 많다. 여기에 **실제 요건·전형·연봉이 다 들어 있으므로** 반드시 회수한다. *공개 링크를 따라가는 것은 우회가 아니다* — 게시자가 의도한 접근 경로다. **로그인·권한이 걸린 파일은 여기서도 우회 금지.**

**PDF 첨부 — 취득 사다리(검증된 순서):**
1. **다운로드 후 텍스트 레이어 추출** — `curl -sSL` 로 받아 **PyMuPDF**(`fitz`)의 `get_text()`. 대부분의 공고 PDF는 여기서 끝난다.
2. **텍스트가 비면 = 스캔본(이미지 PDF)** → PyMuPDF `get_pixmap(dpi=150~200)` 로 **페이지를 PNG로 렌더 → 이미지로 판독**. (OCR 엔진에 의존하지 않는다.)
3. **다운로드가 막히면**(403·로그인·서명 URL) → 사용자에게 **파일을 직접 받아 첨부**해 달라고 요청. 가장 확실하고, 사용자 권한으로 정당하게 접근하는 경로다.

**⚠️ PDF가 있을 거라고 넘겨짚지 않는다.** "한국 기업은 공고를 PDF로 올린다"는 통념은 **회사마다 다르다.** 첨부가 실제로 있는지는 상세 응답의 첨부 필드(§1-(2-b))로 확인하고, 없으면 **"PDF 없음(확인함)"** 이라고 적는다. 있지도 않은 첨부를 찾느라 시간을 쓰지 않는다.
> 실측(2026-07): SK키파운드리는 자사 홈·SK Careers·잡코리아 **세 경로 모두 HTML이고 채용 첨부가 없었다**(자사 도메인의 PDF 2건은 전 페이지 푸터에 박힌 지속가능경영보고서로, 채용과 무관). 반대로 삼성전자 DS 공고에는 첨부가 **있었고**(입사지원서 양식 .docx) 다운로드도 됐다.

**목록 API가 막히면 상세 URL 패턴을 시도한다.** 목록만 보호되고 **상세 페이지는 평범한 GET으로 열리는** 사이트가 흔하다. 검색엔진·다른 보드에서 상세 URL 하나만 확보하면 ID 패턴(`/Detail/R261552` 등)이 드러나고, 나머지는 그 패턴으로 접근된다.
> 실측(2026-07): `skcareers.com`의 목록 API(`POST /Recruit/GetRecruitList`)는 요청 형식이 맞지 않아 실패했고 거기서 포기했는데, **상세는 `GET /Recruit/Detail/{ID}`로 인증 없이 그냥 열렸다.** 목록에서 막혔다고 사이트 전체를 포기하지 않는다.
- ⚠️ **웹 페이지 변환 도구로 PDF 본문을 읽으려 하지 않는다** — 압축 스트림이라 **메타데이터만 나오고 본문은 실패**한다(실측). 반드시 위 1–2번 경로를 쓴다.
- 추출한 요건은 **[T1] 원문**으로 승격하고 **확신도 '높음' + 오차 ±5**로 되돌린다 — 취득 실패로 낮췄던 확신을 회복시키는 가장 강력한 수단이다.

**별도 링크(자체 채용페이지·Notion·Google Docs·구글폼 등):**
- 공개면 그대로 조회. **Notion·Google Docs는 공개 공유 상태일 때만** 읽힌다 — 권한 요구가 뜨면 §1-(1) **G 게이트**로 처리하고 사용자 붙여넣기를 요청한다.
- 구글폼·자체 지원 폼은 **읽기만** 한다. **자동 제출·자격증명 입력을 하지 않는다**(§0).
- 링크가 또 다른 첨부로 이어지면 위 PDF 사다리를 재귀 적용한다.

> **가장 확실한 경로는 사용자 첨부다.** 취득이 애매하면 시간을 쓰지 말고 "이 공고의 PDF/링크를 첨부해 주세요"라고 요청한다 — 1분이면 확신도가 '낮음'에서 '높음'으로 올라간다.

## 2. 공고 발굴 (JD Discovery) — 태스크 ① 발굴 모드
**(1) 탐색 프로파일** (뱅크·프로필에서 자동 생성)
- 핵심 역량·필살기 카테고리 · 타깃 방향(프로필 커리어 방향) · 연차/레벨 · 지역/이동성
- **언어 능력 → 공고 언어 범위**: 언어 근거(자격·경험) 있으면 해당 언어권 공고도 탐색(예: 영어 능력 → 국내 + 영어권·글로벌). 근거 없으면 국내 위주.

**(2) 탐색 대상** (요청일 기준, 공개)
- 국내: 원티드·사람인·잡코리아·리멤버·링크드인 KR·회사 커리어페이지
- 해외/글로벌: LinkedIn·Indeed·회사 커리어페이지·도메인 특화 보드
- 직무/도메인 특화 보드는 런타임 판단으로 추가.
- **스코프 지정(중요):** 국내·해외 모두 같은 공개 웹이다. 검색 도구가 **US 기본 랭킹**이면 국내 결과가 안 나올 수 있으므로, **국내 발굴 시 국내 보드 도메인으로 스코프를 명시**(예: `allowed_domains: wanted.co.kr·saramin.co.kr·jobkorea.co.kr`)해 검색한다. 상세는 공개 부분을 조회하고, 로그인 구간(연봉 "면접 후 결정" 등)은 §1 추론 + `[직접 확인]`. *("국내는 검색 불가"가 아니라 스코프 문제 — 도메인 지정으로 해결.)*
- **커버리지 규율 (recall — 놓치지 않기):** 한 번의 키워드 검색은 불완전하다.
  1. **직무명 변형 다변화** — 사용자 표현(예: 생산기술)만이 아니라 **동의·인접 직무명**(공정기술·설비기술·제조기술·수율·생산혁신·요소기술 등)으로 **여러 쿼리**(역량→N직무 매핑, methodology jd-matching).
  2. **자사 채용홈 + 회사명 검색을 둘 다** — 대기업은 자사 채용사이트를 쓰지만 **애그리게이터에도 회사 명의로 직접 게시하는 경우가 많다.** 둘 중 하나만 보면 놓친다. **타깃 기업 리스트를 만들어 ⓐ 자사 홈 직접 스윕 + ⓑ 애그리게이터에서 `회사명`으로 검색**을 모두 돌린다.
     > 실측 정정(2026-07): 이 문서는 원래 "삼성은 애그리게이터 미게재"라고 단정했으나 **사실이 아니었다.** 삼성전자 DS 경력채용 **82개 직무가 사람인에 삼성전자(주) 명의로 개별 게시**돼 있었고 제목에 D-day까지 표시됐다. `생산기술` 키워드로만 검색해서 못 만난 것이지 없던 게 아니다. **"거기엔 없다"는 단정을 문서에 박아두면 그 채널을 영영 안 보게 된다** — 채널 부재는 확인된 사실만 적는다.
  3. **다중 쿼리·다중 도메인** — 검색은 상위 N개만 반환 → 각도별(직무명·기업·산업)로 재수집해 합친다.
  4. **커버리지 원장(ledger) — 실행 여부를 눈에 보이게 남긴다.** 위 1–3은 **규칙이 있어도 건너뛰기 쉽다**(실제로 두 번 연속 건너뛰었다). 그래서 발굴 보드에 **실제로 돌린 쿼리·도메인·자사홈 목록과 각각의 수확 건수**를 표시한다. 안 돌린 축은 `미실행`으로 뜨게 한다 — **누락이 침묵하지 않게** 하는 것이 목적이다.

  **직무명 사전 (실측 검증 — 회사마다 같은 일을 다르게 부른다):**
  | 사용자 표현 | 같은 일의 다른 이름 | 실측 메모 |
  |---|---|---|
  | 생산기술 | 설비기술 · 공정기술 · 제조기술 · 요소기술 · 생산혁신 · Manufacturing/Process/Equipment Engineer | **삼성전자 DS는 "생산기술"이라는 직무명이 없다.** 직무기술서 82건 중 해당 0건, 대신 **`설비기술`(직군)·`반도체공정기술`·`생산관리`**로 분류된다. '생산기술'로만 검색하면 **구조적으로 0건**이다. |
  | 품질 | 품질보증(QA) · 품질관리(QC) · 신뢰성 · 수율향상 · 수율분석 | 반도체는 '수율'이 품질·생산성 양쪽을 가리킨다 |

  - **회사별 직무 분류 체계를 먼저 확인하고 그 회사 용어로 다시 검색한다.** 자사 채용홈의 직무기술서·직무코드 목록이 그 사전이다(§1-(2-b)로 회수).

  > 실패 사례(학습, 2회 반복): 삼성전자 DS **설비기술·공정기술 경력채용**이 두 차례 검색에서 모두 누락. 1차는 키워드가 '생산기술'에 치우치고 스코프에 `samsungcareers.com`이 빠져서, 2차는 `samsungcareers.com`을 넣었으나 **SPA 미렌더에서 포기**해서(§1-(2) 3번 미실행). 실제로는 공고가 **열려 있었고**(2026-07-13~07-27) 로그인 없이 전문 회수가 가능했다. **규칙이 존재해도 실행을 검증하지 않으면 같은 누락이 반복된다** — 그래서 4번 원장을 둔다.
- **결과 품질 강화(최적 발굴):**
  1. **중복 제거·병합** — 같은 공고가 여러 보드에 뜨면 회사×직무×마감으로 dedupe.
  2. **NCS 직무코드 매핑** — 역량을 국가직무능력표준(NCS) 코드로 변환해 코드 기준으로도 검색(라벨 편차 우회, 누락 최소화).
  3. **오버레이** — 각 공고에 **연봉 밴드**(§3)·**커뮤니티 시그널**(§5)을 붙여 한 화면에서 판단.
  4. **정기 재검색(알림)** — 저장한 탐색 프로파일로 주기 재발굴(→ 지원 히스토리에 '신규' 표기). 스케줄은 사용자 선택.

**(2-b) 최대 발굴 원칙** — 정확 매치만이 아니라 **직무·전공 유사 + 커리어 발전 가능성**까지 넓게 발굴한다(인접 직무·성장 경로 포함). 소수만 뽑지 말고 가능한 많이 모아 점수로 걸러 순위화.

**(2-c) 신선도 게이트 (수집 즉시 — 채점보다 먼저)**
마감된 공고를 채점하는 건 리소스 낭비이고, 사용자에게 **지원 가능한 것처럼 보이는 착시**를 준다.

> ⛔ **마감일을 추정으로 채우지 않는다(날조 금지의 가장 흔한 구멍).** 보드 검색 목록은 대개 "즉시 지원"·"홈페이지 지원"만 보여주고 **날짜를 주지 않는다.** 그때 그럴듯한 날짜를 적으면 D-day·만료 판정·정렬이 **전부 허구 위에서 돌아간다.** 날짜는 **공고 원문에서 확인한 것만** 기록하고(`dlVerified:true`), 확인 못 했으면 **비워 둔다.** 비면 화면에 `마감 [확인 필요]`로 뜨고 D-day를 만들지 않으며, **만료 판정도 하지 않는다**(모르는 것을 안다고 하지 않는다).
> 실측(2026-07): 발굴 11건 중 **10건의 마감일이 검색 결과에 없던 추정치**였다. 그중 하나(에스케이키파운드리)는 다른 보드에서 **2025-02-16 마감**으로 확인돼, 1년 5개월 지난 공고를 `Δ −8 보합`의 최상위 후보로 올려놓고 있었다. 신선도 게이트가 있었는데도 못 막았다 — **게이트가 날짜의 출처를 구분하지 않았기 때문이다.**

- 각 공고에 **게시 상태**를 먼저 확정: `모집중` / `마감임박(D-7 이내)` / **`만료`** / `상시` / `마감 [확인 필요]`(확인 불가 — 기본값).
- **마감 미확인은 `최우선`으로 승격시키지 않는다.** 열려 있는지 모르는 공고에 "즉시 지원"이라고 말할 수 없다. 사용자가 원문을 열어 확인하면 승격된다.
- **만료는 목록에서 배제하지 않되**(자유도 보존 — 재공고·유사 공고 단서가 된다) **채점하지 않는다.** `만료 — 재공고 시 재검토`로 분리 표시하고 리소스를 쓰지 않는다.
- **만료 비중이 높으면 쿼리를 의심한다** — §1-(3)의 연·월 키워드 혼입 또는 오래된 색인 히트. 쿼리를 고쳐 재수집한다.
- **회전문 탐지 연계:** 같은 회사×직무가 **반복·상시 게재**되면 §3 적신호(이직률 신호)로 넘긴다. 발굴 이력(`.private/applications/`)과 대조.

**(2-d) 기준선 등록 + 자사 공고 처리 (재직자 필수)**
- **발굴 전에 현직(또는 최근 직장)을 기준선으로 등록**한다: 회사·직급·지역·규모 + **직장 품질 5축 점수**(evaluation §5.8-c). 기준선이 없으면 "품질 52"가 상향인지 하향인지 판정할 수 없다.
- **자사 공고 자동 라벨:** 발굴 결과에 **현직 회사**가 나오면 `사내 전배 — 이직 아님` 배지를 붙이고 **4분면에서 제외**해 **기준선 카드**로 따로 보여준다(사내 이동은 판단축이 다르다: 사내 절차·평판·전배 이력).
- 무직·첫 취업이면 기준선 없음 → Δ 미표기, 절대 점수 + evaluation §5.7 시장 위치 레이어로 대체.
> 실패 사례(학습, 2026-07 실사용): LG이노텍 **재직자**에게 LG이노텍 구미 공고가 `최우선` 1위로 떴다. 적합도 계산은 옳았지만 **이직 후보가 아니었다.**

**(2-e) 발굴 수율 규칙 → 채널 전환 (더 훑지 말고 채널을 바꾼다)**
수집·채점을 마치면 **유효 최우선 건수**를 센다 — `적합도 ≥65 ∧ 품질 ≥65 ∧ 확신 중간 이상 ∧ 자사 아님 ∧ 만료 아님`.
- **0건이면 이 채널이 고갈된 것이다.** 같은 보드를 더 훑지 말고 [`job-search-ops.md`](job-search-ops.md) §2-b로 넘겨 **채널을 전환**한다: 자사 채용홈 직접 · 서치펌·헤드헌터 · 리퍼럴 · 컨설팅펌 직접 지원.
- 사용자에게 전달할 판정 문장: **"공고가 없는 게 아니라 이 채널에 없다."**
> 실패 사례(학습, 2026-07 실사용): 잡코리아 '생산기술' 4,719건 모수에서 11건을 발굴했는데 유효 최우선 **0건**. 대기업 경력 생산기술은 **자사 채용홈·서치펌으로 빠지기 때문**이고, 공개 보드 모수는 중견·중소 중심이다. 보드를 더 훑어도 결과가 바뀌지 않는 구조였다.

**(3) 산출 = 공고 발굴 보드** ([`templates/jd-discovery.html`](../templates/jd-discovery.html))
각 공고 항목:
- **적합도 점수(0–100)** + 등급(상/중상/중/하) + 확신도. **4축 근거 막대**: 직무유사 · 전공·역량유사 · 발전가능성 · 무게중심 충족. (합성 점수이되 축·확신도로 분해 — 허위 정밀감 방지, Score Caps.)
- **직무 한줄 요약** (필수) · 회사 · 요구 핵심(추론 시 `[직접 확인]` 플래그) · **마감 D-day** · **공고 링크(필수)** · 출처·조회일·Tier.
- **직장 품질 + 기준선 델타** `품질 52 (Δ −19 · 하향)` — 재직자면 필수(evaluation §5.8-c).
- **상태 배지**: `만료` / `사내 전배` / `오버스펙` / `연차 미달` / `⚠️ 적신호` / `[확인 필요]`(취득 실패 — §1-(4) 승격 가드).
- **위시리스트 체크박스** → 선택 공고를 `.private/applications/` '관심' 단계로 저장(일정관리 연동).
- 정렬: 적합도순(기본)·마감 임박순·발전 가능성순·**품질순·Δ순**. 필터: 국내/해외/위시리스트/최우선/적신호/**상향만**. **취득 실패 URL은 상단 `GATED`에 유형코드와 함께 전부 명시**(§1-(4)).
- 공고는 **실제 결과만·날조 금지**, 링크는 실 URL.

**(4) 핸드오프**: 선택 공고 → ① 심층 매칭(5-D Prism + 매칭 매트릭스). 위시리스트 공고 → `.private/applications/` '관심' 저장 → [`application-tracker.html`](../templates/application-tracker.html)에서 D-day 일정관리(§6.0 체이닝, 중복 방지).

## 3. 기타 런타임 수집 (태스크별)
- **① 직장 품질·적신호 (evaluation §5.8 — "갈 만한 곳인가")**:
  - **안정성(S/A)**: **DART 전자공시**(재무제표·감사의견·업력) · **국민연금/고용보험 가입자 수 추이**(인력 증감 = 성장/축소 신호) · 공식 IR·보도.
  - **보상(A/B)**: 공개 연봉 통계·직무 보상 레인지(§3 연봉과 동일 규율 — 고신뢰 comp는 로그인월 주의).
  - **성장·배움(A)**: 공고의 기술 스택 현대성 · 팀 규모·사수 유무 언급 · 교육·사내이동 제도(공식).
  - **문화·워라밸**: 공식 제도(A) + **커뮤니티 시그널(B/C — §5, 반드시 분리 표기·사실 인용 금지)**.
  - **⚠️ 적신호(안전 — 점수와 별개로 항상 경고)**: **임금체불 공개 이력**(고용노동부 공개 명단 등) · **동일 공고 상시·반복 게재**(회전문 = 이직률 신호, 발굴 이력으로 탐지) · 과도한 수습 조건 · 4대보험 미가입 정황 · 대표/법인 쟁송 보도 · **채용 과정에서 비용 요구**(사기 신호). → 근거·출처·조회일 명시, 미확정은 `[확인 필요]`, **자동 배제는 하지 않고 경고만**(판단은 사용자).
- **③④ 면접**: 기업 인재상·핵심가치·리더십원칙·전형 단계·현직자 후기(공개).
- **⑥ 연봉**: 시장 밴드·직무 보상 레인지. **정직한 천장**: levels.fyi·블라인드·원티드인사이트 등 고신뢰 comp는 로그인월(→ §1 추론 + 사용자 확인), 공개 통계·기사 위주로 Tier 낮춤.
- **⑦ 로드맵**: 산업·직무 트렌드·미래역량 수요. **직급 로드맵 보강(methodology §6 roadmap §4.6)**: 회사 **직급 체계·호칭 개편**(뉴스·공식 = S/A), **상위 조직/사업부 구조**(DART 사업보고서·IR·보도 = A), **공식 현직자 인터뷰·채용 브랜딩**(커리어 성장 서사 = A, 정성)으로 **일반 베이스 라더를 실제 회사 근거로 상향**. 단 **구체 승진 요건**(체류연한·고과 커트라인·심사)은 대개 내부·블라인드 로그인월 → §1 추론 + `[직접 확인]`, **커뮤니티 후기는 B/C**(편향·구식·사업부별 상이, §5). **유출 내부문서·팀 상세 조직도 미사용.** 최종 근거 = **사용자 인터뷰 + 사내 규정(T1)** — 공개 자료는 인터뷰를 날카롭게 하는 입력이지 확정 아님.
- **①/②**: JD 원문·기업 최신정보(7-Lens 입력).

## 4. 인용·표기
- 리포트 하단 '참조 출처'에 평문으로: 출처명 · Tier · 조회일.
- 추론/미확인은 **반드시 플래그**. 확정 요건은 사용자 확인 후 [T1] 승격.

## 5. 커뮤니티 시그널 (현직자·경험자 후기 — 저신뢰 참고)
공식 정보(S/A)가 말하지 않는 **적나라한 현실**(실제 문화·워라밸·연봉 현실·전형 난이도·조직 리스크)을 **참고용으로 병행** 제시한다. 신뢰도는 낮지만 방향 판단에 도움이 된다.

- **소스**: 블라인드·잡플래닛·Glassdoor·Reddit(회사/산업 서브레딧)·직무 커뮤니티(OKKY·긱뉴스 등)·유튜브 후기. 공개 범위만(로그인월은 §1 추론 + `[직접 확인]` 플래그; 블라인드는 대개 게이트).
- **Tier 고정 = B(커뮤니티 주의) / C(단일·미검증)**. **S/A 승격 금지 · 사실로 인용 금지.**
- **표기**: 공식 정보와 **시각적으로 분리된 "커뮤니티 시그널" 블록** + 명시 면책 — *"개인 경험·편향·과장 가능, 사실 아님, 방향 참고용."*
- **노이즈 필터**: **반복 테마(독립 3+ 소스) = 신호 / 단발 불만 = 노이즈**로 구분. **불만 편향**(퇴사자·화난 사람 과대표집) 명시. 대략의 표본 규모·시점 표기.
- **작업용 전용**: 제출용·대외 산출물엔 **미포함**(§6.0 계약 #5·#7). 커뮤니티 주장을 산출물의 사실 근거로 쓰지 않는다.
- **활용처**: ① 히든배리어·근무현실 / ③④ 전형 난이도·면접 후기·실제 조직문화 / ⑥ 연봉 현실·협상 여지.
