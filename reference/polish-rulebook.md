# reference/polish-rulebook.md — 윤문 룰북 (취업 문서 전용)

> AI가 쓴 티를 빼되 **지원자를 지운다면 실패다.** 이 파일은 집행 사전(SSOT)이고,
> [`writing-voice.md`](writing-voice.md)가 계약(무엇을 언제 돌리는가)이다.
> 임계값의 SSOT는 [`../scripts/check_polish.py`](../scripts/check_polish.py) — 문서와 코드가
> 각자 숫자를 적으면 어긋나므로, 이 파일 §7 표는 스크립트 상수를 인용할 뿐이다(게이트가 대조).
>
> 분류 축과 심각도 3단계 모델은 외부 저작물을 참고했다 → [`../NOTICE`](../NOTICE).
> 처방·임계·예문·반전 목록은 **취업 도메인 실측으로 새로 썼다.**

## §0. 대원칙 — 순서가 곧 규칙이다

1. **의미 불변이 최우선.** 사실·수치·고유명사·기간·역할·기여도는 **글자 단위로 보존**한다.
   모호해도 임의 보강 금지. 이건 문체 문제가 아니라 [`evaluation.md`](evaluation.md) §8 claim-audit의 영역이다.
2. **빼기 전용.** 치환은 AI 티를 **빼는** 방향이다. 처방 예시의 어휘를 원문에 없던 자리에
   새로 심지 않는다. 원문보다 격식을 올리지 않는다.
3. **국소성.** 탐지된 구간만 고친다. 문단을 통째로 다시 쓰지 않는다.
4. **개성 > 표준.** 지원자 고유의 어휘·사례·표현은 "표준 자소서 문체"보다 우선한다.
   *가장 흔한 실질 피해는 AI 티가 남는 게 아니라 지원자가 지워지는 것이다.*
5. **축을 모르면 돌리지 않는다.** §1 참조.

## §1. 문서축 판정 — 틀리면 파이프라인 전체가 틀린다

축은 넷이다: **[자]** 자소서(서술형 산문) · **[력]** 이력서·경력기술서(불릿) ·
**[영]** resume/cover EN · **[일]** 일반 산출(리포트·로드맵·모범답변·스크립트).

★ **[일]이 폴백이다.** 스킬 산출의 다수가 여기 속한다(분석형 ①③④⑤⑥⑦은 report.html).
폴백을 [자]로 두면 자소서 규칙(종결 일관성·분량 밴드)이 리포트에 걸려 오탐이 쏟아진다 —
**규칙이 많은 쪽이 아니라 오탐 비용이 낮은 쪽**이 보수적이다. [일]은 §4 공통 티(TR·CL·ST-1)만 보고
종결·분량·변경률은 적용하지 않는다.

**판정 근거는 `문서유형` 입력값이다** ([`../SKILL.md`](../SKILL.md) §② 공통 입력:
`문서유형(자소서·이력서KR·resume EN·cover EN·포트폴리오)`). 이미 사용자에게 받는 값이라 추정이 아니다.

| `문서유형` | 축 |
|---|---|
| 자소서 · cover EN(국문 규범 적용 시) | **[자]** |
| 이력서KR · 경력기술서 | **[력]** |
| resume EN · cover EN | **[영]** |
| 포트폴리오 | **[자]** 준용(서술 블록만), 레이아웃 규칙 미적용 |
| 그 외(리포트·로드맵·모범답변·스크립트) | **[일]** |

> ★ **템플릿으로 축을 판정하지 않는다.** 처음 설계는 `a4-doc.html → [력]`로 매핑했는데,
> SKILL.md는 **국문 자소서도 a4-doc으로 렌더**한다고 명시한다. 그 매핑을 쓰면 자소서를
> 정상 경로로 뽑는 순간 [자] 카탈로그가 통째로 비활성돼 카운트가 전부 0 → **"AI 티 없음"으로
> 오통과**한다. 검사를 안 한 것이 통과로 보이는 최악의 실패다.
>
> 템플릿은 **보조 신호**로만 쓴다(`문서유형`이 빈 경우에 한해 `cover-letter.html`→[자],
> `resume-ats.html`→[영]). **둘 다 없으면 판정을 보류하고 사용자에게 묻는다** — 추정하지 않는다.

## §2. 불가침 — 윤문이 절대 건드리지 않는 것

아래는 **탐지 대상에서 제외**하고, 분량이 모자라도 **트림하지 않는다.**

- **수치 원자** — 숫자·단위·통화·기간·비율. 재배치는 되지만 **값 변경·신규 삽입은 금지.**
  *원문에 없던 수치를 넣는 것은 윤문이 아니라 **허위 기재**다.*
- **고유명사** — 회사·제품·기술·자격·기관·직급.
- **역할 경계와 기여도** — "내가 한 것 / 팀이 한 것"의 구분, 기여율 표현.
- **hedge** — "약", "추정", "체감", "일부". 지우면 단정이 되고 그건 claim 위반이다.
- **출처 라벨** — `[T1]`/`[T2]`/`[T3]`/`[확인 필요]` 및 EXP-ID.
- **실패·한계 서술** — 성격 단점, 극복 과정의 실패 부분(methodology §3이 요구하는 승부처다).
- **Insight/Learning 명제** — 경험에서 얻은 원칙. ★ `이를 통해 ~를 배웠습니다`는 **표지어만** 티다.
  표지어(`이를 통해`)는 지우되 **배운 내용 자체는 지우지 않는다** — 필살기 3요소의 '인사이트'가 사라진다.
- **두괄식 첫 문장의 주장** — 문항 첫 문장의 명사구 주장(methodology §3). 서술문으로 풀지 않는다.

> ★ 사용자가 "더 줄여줘"를 반복해도 불가침을 자동으로 깎지 않는다. 자수 압박은 실제 상황이므로
> **"그 문장을 통째로 뺄까요?"로 되묻는다** — 조용히 hedge를 지우면 사용자는 자기가 단정한 줄 모른다.

> ★ 모델 안에는 범용 윤문 지식이 이미 들어 있어서, 지시하지 않아도 아래가 **되살아난다.**
> 그래서 목록을 1급 시민으로 둔다. 15건 중 하나라도 발동하면 취업 문서가 규범을 위반한다.

| 범용 처방 | 이 도메인에서 | 왜 |
|---|---|---|
| 문단 첫 문장 요약 공식 해체 | **금지 — 정확히 반대** | 두괄식이 절대 규범. 평가자는 첫 문장만 읽는다. 결론·성과가 맨 앞이어야 한다 |
| 명사구 주장 → 서술문화 | **금지** | methodology §3 "모든 문항 첫 문장은 강력한 '주장'"(예: `데이터 기반 합리적 의사결정`) |
| 불릿 → 산문 전환 | **[력] 금지 / [자] 적용** | 이력서는 불릿이 문서 형식 자체. 산문화하면 스캔 가독성·ATS 파싱이 붕괴 |
| 섹션 헤딩 제거 | **금지** | 경력/학력/스킬 헤딩이 없으면 ATS 파싱 불가. 자소서 문항 소제목도 국내 관행상 권장 |
| 조사 복원(명사 나열 해체) | **[력] 금지 / [자] 적용** | `물류 재고 회전율 20% 향상` 같은 압축 명사구가 불릿의 표준 문법 |
| 영어 병기 축소 | **[력] 금지** | JD 키워드 매칭·ATS 검색에 `고객관계관리(CRM)` 병기가 유리 |
| 종결어미 다양화 | **[력] 금지 / [자] 완화** | 이력서는 종결 **통일**이 규범(명사형 또는 `~함`). 자소서는 합쇼체 고정 |

| 장문(100자+) 삽입 | **금지** | 글자수 예산을 잡아먹고 두괄식을 흐린다 |
| 문장 길이 편차 강제 | **완화** | 리듬 다양화는 권장이되 **강제 삽입 금지**(§0-2 빼기 전용) |
| 볼드 제거 | **[력] 금지** | 이력서 성과 수치 강조는 스캔을 돕는다 |
| 숫자 인덱싱 `1) 2) 3)` 제거 | **완화** | 문항 구조를 드러내는 용도면 보존 |
| 콜론 부제 헤딩 제거 | **[력] 금지** | 섹션 제목 형식 |
| 결말 상투구 전량 삭제 | **부분 반전** | 접속 표지(`결론적으로`)만 삭제, **결론 문장 자체는 보존**(두괄식 마감) |
| 열거 도입 삭제 | **부분 반전** | `크게 세 가지로` 같은 예고는 보존 가능, `다음과 같은` 군더더기만 삭제 |
| 3인칭 대명사 삭제 | **해당 없음** | 영어 원문 번역 맥락 전용 규칙. 자소서·이력서는 자생 한국어 |

## §4. 티 카탈로그 — 취업 문서 실측 기준

심각도: **치명**(1회로 티) · **반복**(문서 3회+에서 티) · **누적**(다른 티와 겹칠 때 강화)

### TR — 번역투 (둘 다 적용)

| ID | 심각도 | 패턴 → 처방 |
|---|---|---|
| TR-1 | 치명 | `~에 있어(서)` → `~에서` / `~을 볼 때` |
| TR-2 | 치명 | `~을 가지고 있다` → `~이 있다` / `~이 강하다`. [력]은 명사 종결(`정보처리기사 취득`) |

| TR-5 | 치명 | `이루어졌다`·`만들어졌다` 자동 피동 → `협업했다`. 누가 했는지 지우지 않는다 |
| TR-6 | 반복 | `~을 통해` (문단 3회+) → `~로`·`~해서`. **1~2회는 보존** |
| TR-7 | 반복 | `~에 대해(서)` → 목적격 조사로 직결 |
| TR-8 | 반복 | `~와 관련하여/관련된` → `~에`·`~의` |
| TR-9 | 반복 | `~을 바탕으로`·`~에 기반하여` → `~로`·`~를 근거로` |
| TR-10 | 반복 | 관형구 3어절+ 좌향 수식 중첩 → 문장 분리 |
| TR-11 | 반복 | 이중 조사 `~에서의`·`~으로의` → 절로 풀기(`현장에서의 경험` → `현장에서 쌓은 경험`) |

## §5. 판정 — 변경률 단독으로 중단하지 않는다

> ★ 변경률은 **피해를 못 잡는다.** "지원자 경험을 통째로 갈아엎는" 사고에서 문자 변경률은
> 임계에 도달조차 하지 않고, 반대로 [력]의 **종결 통일**(`~을 개선하였습니다` → `~ 개선`)은
> 정상 작업인데 변경률이 손쉽게 40%를 넘는다. 변경률만 보면 **시킨 일을 중단시키고 사고는 놓친다.**

판정은 **보존 지표**가 먼저다.

| 지표 | 무엇을 보는가 | 위반 시 |
|---|---|---|
| **수치 신규 삽입** | 원문에 없는 숫자가 결과에 있는가 | **즉시 중단** — 허위 기재 |
| **수치 소실** | 원문 수치 원자가 결과에 없는가 | **즉시 중단** |
| **고유명사 소실** | 회사·기술·자격 표기가 사라졌는가 | **즉시 중단** |
| **출처 라벨 소실** | `[T1]`/`[확인 필요]`/EXP-ID | **즉시 중단** |
| **JD 필수 키워드 소실** | 포함 키워드가 남았는가 | **즉시 중단** — ATS **매칭 점수**가 깨진다(파싱과 별개). 동의어 치환은 사람 눈엔 멀쩡하고 ATS에선 탈락이라 보이지 않는 손실이다 |
| 변경률 | 참고값 | **경고만.** 단독 중단 사유 아님 |

**종결 형식 통일·조사 정리 같은 구조적 정규화는 변경률 계산에서 제외**한다(정규화 후 비교).
그렇지 않으면 룰북이 시킨 일을 룰북이 막는다.

## §6. 분량 예산 — 기준축을 모르면 판정하지 않는다

자소서는 **글자수 상한이 제출 가능 여부를 가른다.** 상한 초과 = 제출 불가.

- **상한에 종류가 있다.** `quota`(자소서 문항 — 하한 적용) vs `cap`(LinkedIn Headline 220자 같은
  플랫폼 필드 — **하한 미적용**). ★ 모든 상한에 하한을 걸면 "220자 헤드라인을 198자 이상 쓰라"는
  말이 된다 — [`linkedin.md`](linkedin.md) §1의 상한은 넘지 말라는 뜻이지 채우라는 뜻이 아니다.
- **밴드로 본다(quota만)** — 하한(상한의 90%)~상한. 하한 미달은 "분량을 덜 썼다"는 신호일 뿐 오류가 아니다.
- **기준축**(공백 포함/제외)은 **회사마다 다르고 문항마다 다르다**(`cover-letter.html`의 `limbase`).
- ★ **기준축을 모르면 판정을 보류한다.** 한국어 자소서의 공백 비율은 20~25%라
  **오판 폭이 밴드 폭(10%)보다 크다** — 같은 글이 기준축에 따라 통과도 되고 초과도 된다.
  추정해서 판정하면 밴드가 무의미해진다. **두 수치를 모두 배출하고 기준축을 물어본다.**
  판정이 꼭 필요하면 **방향별로** 보수적으로 잡는다 — 상한은 큰 값(공백 포함), 하한은 작은 값
  (공백 제외). 양쪽 모두 안전한 구간만 통과시키고, 밴드가 좁아졌다는 사실을 사용자에게 고지한다.
- **증량 재료는 뱅크의 원자로 한정.** 하한을 채우려고 문장을 늘리면 방금 뺀 상투구를 다시 심게 된다.
  새 문장은 **EXP-ID·[출처]·Tier가 붙은 뱅크 원자**에서만 가져오고, 삽입 시점에 그 라벨을 함께 단다
  (§8의 claim-audit이 1:1 대조할 수 있어야 한다). ★ '꼬리질문 방어 문장'은 재료가 아니다 —
  뱅크 사실이 아니라 생성물이라 claim-audit이 거부한다.
  재료가 없으면 **분량 미달을 그대로 보고**한다. 지어내서 채우지 않는다.
- ★ **증량하면 티 스캔으로 되돌아간다.** 추가한 텍스트는 §4 스캔을 거치지 않은 신규 문장이다.
  **추가분에 한해** §4를 1회 재적용한다(전체 재스캔 아님 — 무한 루프 방지).
- **트림 후 claim-audit 재실행.** 줄이는 과정에서 hedge·역할 경계가 깎였는지 다시 본다.

## §7. 임계값

임계의 SSOT는 [`../scripts/check_polish.py`](../scripts/check_polish.py) 상수다.
게이트가 이 표와 스크립트를 대조하므로 **한쪽만 고치면 스모크가 실패한다.**

| 항목 | 값 | 성격 |
|---|---|---|
| 분량 하한 비율 | 0.90 | 경고 |
| 분량 상한 | 사용자 지정 | **중단** |
| 변경률 경고 | 0.50 | 경고 |
| 종결 일관성 하한 | 0.90 | 경고 |
| 수치/고유명사/라벨 보존 | 1.00 | **중단** |

★ **종결 일관성 분모에서 제외**: 문항 첫 문장(두괄식 명사구 주장) · 소제목 · 불릿 · 인용.
제외하지 않으면 **규범을 정확히 지킨 자소서가 영구 보류된다** — 600~800자 문항은 문장이
8~12개라 규범이 요구하는 명사구 주장 1개만 들어가도 비율이 0.91로 떨어진다.

★ **자가 산출 금지.** 변경률·글자수·보존율은 에이전트가 추정하지 않고
`check_polish.py` 출력값을 **인용**한다.

## §8. 파이프라인

```
초안/리라이트 완료
  → [1] 축 판정(§1) — 모르면 중단하고 질문
  → [2] 티 스캔(§4) — 축에 해당하는 절만, §3 반전 목록 먼저 확인
  → [3] 국소 치환(§0-2 빼기 전용, §2 불가침 제외)
  → [3b] 정량 마감 점검 — 성과 문장 중 **수치로 닫히지 않은 것**을 목록화.
         없으면 P2 정량화 대화(뱅크 write-back). ★ 지어내지 않는다.
         액션 동사 분산은 writing-voice §3 매핑 사용.
  → [4] check_polish.py 실행 — 보존 지표 위반 시 롤백(§5)
  → [5] 분량 예산(§6) — 기준축 없으면 두 수치 배출 후 질문
  → [6] 트림했으면 claim-audit 재실행(evaluation §8)
  → [7] 제출 렌더
```

윤문은 **마지막 관문**이다. 리라이트보다 뒤에 온다 — 앞에 두면 이후 수정이 게이트를 안 거친다.
