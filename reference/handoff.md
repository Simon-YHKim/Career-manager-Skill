# reference/handoff.md — 세션 핸드오프 (career 최적화 내재화)

> `simon-handoff`(SimonK-stack)의 **"영속 + 재개 보장"** 규율을 career에 맞게 최적화·내재화.
> 트리거: "핸드오프", "인수인계", "다음 세션 준비", "이어서 하게 저장". SKILL §2가 참조.
> **핵심 최적화(원본과의 차이):** career 세션 상태엔 **개인정보**(작성 중 자소서·위시리스트 실공고·
> 프로필 파생 문맥)가 있다. 원본은 `docs/HANDOFF.md`를 **main에 머지**하지만, career는 그러면
> D-6 위반이므로 **PII는 `.private/`로 라우팅한다.**
> **저장소가 public이면 gitignore로 제외하고(A), private이면 사용자 동의 하에 추적해(C) 크로스-컨테이너 완전 재개**를 만든다.
> **핸드오프는 세션 끝의 이벤트가 아니라 세션 내내의 규율이다** — §컨텍스트 관리.

## 두 갈래 (무엇을 이어받나로 결정)

### A. 개인 세션 핸드오프 (기본 — 취업 준비 세션)
사용자 취업 준비 상태를 이어받는다. **PII 포함 → `.private/session-state.md` (gitignore, 커밋 금지).**
- **영속:** `.private/`는 D-6대로 사용자가 durable하게 보관(repo private+gitignore / CC 메모리 / 외부 파일). 그 저장소가 유지되면 새 세션이 읽어 재개.
- **정직한 한계:** `.private/`는 gitignore라 **`git pull`로는 안 옴**. 임시 컨테이너가 폐기되면 사용자가 `.private/`를 다시 제공해야 함(또는 durable 저장 선택 시 유지).
  → **이 한계는 모드 C로 해소된다.** 저장소가 private이고 사용자가 동의하면 `.private/`를 추적해 크로스-컨테이너 완전 재개가 된다. **"PII라서 원천적으로 불가"가 아니라 "공개 저장소에서 불가"였다** — 조건이 바뀌면 답도 바뀐다.
- **뱅크는 이미 durable** — 재입력 불필요분(경험 원자)은 `experience-bank.md`가 담당. 핸드오프는 **휘발 상태만**: 진행 태스크·진행률·활성 다이얼·작성 중 초안·위시리스트·미결 질문.

### B. 스킬 개발 핸드오프 (비-PII — 이 스킬을 빌드/개선하는 세션)
개발 상태엔 PII가 없다 → 원본 `simon-handoff` 그대로: `docs/HANDOFF.md`에 **prepend + main 머지** → 새 세션이 `git pull origin main`로 이어받음.

### C. Private 저장소 추적 (크로스-컨테이너 **완전** 재개) ⭐
> A의 "임시 컨테이너가 폐기되면 사용자가 다시 제공해야 함"이라는 한계를 **없애는** 모드.
> **원격 세션(컨테이너 휘발)에서는 이게 사실상 기본값이어야 한다** — 안 하면 매 세션 재입력이다.

**조건 (셋 다 충족해야 진입):**
1. 저장소가 **private임을 실제로 확인** — 사용자 말만 믿지 말고 API·설정으로 검증한다(`visibility: private`).
2. 사용자가 **명시적으로 동의** — 아래 되돌릴 수 없음을 고지한 뒤.
3. 진짜 비밀(토큰·비밀번호·인증서)은 **여전히 제외** — PII와 시크릿은 다르다.

**절차:**
- `.gitignore`에서 `.private/` 제외를 풀고, **왜 스킬 기본값(gitignore)에서 벗어나는지**를 `.gitignore` 상단과 README에 주석으로 남긴다.
- 커밋·푸시. 이후 뱅크·포트폴리오·지원 히스토리·세션 상태가 전부 저장소에 남는다.
- **재개는 `git clone`(또는 `pull`) 하나로 끝난다** — 새 컨테이너·새 세션·다른 기기 어디서든.

**⚠️ 반드시 고지할 것 (되돌릴 수 없다):**
> 한번 커밋된 개인정보는 **git 히스토리에 영구히** 남는다. 저장소를 나중에 public으로 되돌리면 **과거 커밋까지 전부 노출**된다. public 전환이 필요해지면 **먼저 히스토리에서 제거**해야 한다.

**모드 선택 기준:**
| 상황 | 모드 |
|---|---|
| 로컬·지속 환경, 저장소 public | **A** (`.private/` gitignore 유지) |
| 원격·임시 컨테이너 + 저장소 private + 동의 | **C** ⭐ |
| 이 스킬 자체를 개발 | **B** |

## 실행 절차 (공통 규율)

**1) 상태 수집** — git 상태(HEAD·머지된 PR·working tree) + 대화에서: 이번 세션 성과, 다음 작업 큐, 사용자가 명시한 영구 정책, 핵심 파일 위치.

**2) prepend (덮어쓰지 않음)** — 파일 맨 위에 새 `## Latest — YYYY-MM-DD / 요약` 블록 추가. **직전 블록의 `## Latest —`는 평문 `## <date>`로 강등**(Latest 마커는 항상 최신 1개만). 이전 블록 본문은 보존.

**블록 템플릿:**
```markdown
## Latest — YYYY-MM-DD / <한 줄 요약>

### 어디까지 왔나
- 진행 태스크: <태스크·단계> · 진행률: <…>
- 활성 다이얼: 출력모드/언어/평가강도/PR강도/전문용어
- 작성 중 초안: <문서유형·회사·문항 위치>
- 위시리스트: <공고 N개(회사·마감)>

### 다음 작업 큐
| # | 작업 | 크기 | 권장 |
|---|---|---|---|
| A | <…> | small/med/large | ⭐ <이유> |

### 미결 질문 / 사용자 결정 대기
- <…>

### 적용 중인 정책 (영구)
- <예: [T3] 대외 미사용, 원천징수=민감 PII, 국내 발굴 시 도메인 스코프 등>

### 다음 세션 재개
- (A) `.private/session-state.md` 로드 → 진행 태스크부터
- (B, 개발) `git fetch origin main && git pull && cat docs/HANDOFF.md`
- (C) `git clone <private-repo>` → `.private/session-state.md` + `experience-bank.md` 로드 → 재개 검증 5항목
```

**3) 영속 처리**
- **A(개인):** `.private/session-state.md`에 저장. **커밋 금지**(gitignore 확인). durable 보관 안내.
- **B(개발):** `docs/HANDOFF.md` prepend → 브랜치 `handoff/<date>` → commit·push·PR → **CI 없으면(또는 green) main 머지**. PR 본문에 Latest 블록 인라인(fallback).
- **C(private 추적):** `.private/session-state.md` prepend 후 **커밋·푸시**. 푸시까지 해야 재개가 보장된다 — 로컬 저장만 하고 끝내면 컨테이너와 함께 사라진다.

**4) 재개 안내** — 사용자에게 복붙 블록 1개 + fallback:
- A: "다음 세션에서 `.private/session-state.md` 열고 '이어서'라고 하세요."
- B: `git fetch origin main && git pull origin main && cat docs/HANDOFF.md` + PR URL·raw URL·branch fallback.
- C: "새 세션에서 이 저장소를 열고 '이어서'라고 하세요 — 뱅크·포트폴리오·지원 히스토리까지 전부 따라옵니다." 

## 컨텍스트 관리 — 핸드오프는 **끝에 하는 일이 아니라 내내 하는 일** ⭐

핸드오프를 "세션 끝에 한 번"으로 다루면 늦다. 컨텍스트가 차면 **가장 중요한 맥락부터 사라지고**, 그때는 이미 요약할 원본이 없다. 규율은 하나다:

> **대화는 휘발한다. 파일은 남는다. 잃으면 안 되는 것은 생긴 즉시 파일로 보낸다.**

**① 즉시 파일화 (대화에만 두지 않는다)**
| 생긴 것 | 즉시 갈 곳 |
|---|---|
| 사용자가 준 사실(수치·기여도·직급·연락처) | `experience-bank.md` — **되묻지 않기 위해** |
| 확정된 판단·용어 정의 | 뱅크의 `## 용어 정의` |
| 발굴 결과·조회 실패 유형 | `.private/applications/_discovery-log.md` |
| 산출물(문서·보드) | 파일로 저장 후 **대화엔 요약만** |
| 사용자가 정한 정책 | `session-state.md`의 `적용 중인 정책(영구)` |

**② 대화에 원문을 쏟지 않는다** — 긴 HTML·JSON·목록은 파일로 쓰고 **핵심 N줄만** 대화에 남긴다. "전체를 보여드릴까요?"는 필요할 때만.

**③ 반복 조회는 캐시한다** — 같은 페이지를 두 번 긁지 않는다. 결과를 파일로 두고 다음엔 그걸 읽는다.

**④ 압박 신호가 오면 진행 중이어도 스냅샷** — 태스크가 안 끝났어도 **지금까지의 상태**를 저장한다. "끝나면 저장하겠다"가 가장 흔한 유실 원인이다.

**⑤ 세션이 길어지면 뱅크를 다시 읽는다** — 누적 대화의 "기억"이 아니라 **파일에서 다시 근거를 긷는다**([`evaluation.md`](evaluation.md) §8 claim-audit). 긴 세션일수록 드리프트가 크다.

## 재개 검증 — 이어받았는지 **확인**하고 시작한다

새 세션 첫 턴에 아래를 확인하고, 결과를 **사용자에게 1줄로 보고**한다(조용히 넘어가면 반쯤 이어받은 채로 진행하게 된다):

1. **상태 파일 존재·최신성** — `session-state.md` 최상단 `## Latest` 날짜가 언제인가
2. **뱅크 로드** — `experience-bank.md`의 미확정 항목(`[확인 필요]`)이 무엇인가
3. **진행 중 태스크** — 어디서 멈췄고 다음 큐가 무엇인가
4. **미결 질문** — 사용자 답을 기다리던 것이 있으면 **먼저 묻는다**
5. **모드 C면 `git log -1`** — 마지막 커밋이 핸드오프 시점과 맞는가

> 하나라도 비면 **"이어받지 못했다"고 말하고** 사용자에게 파일을 요청한다. 빈 상태로 추측해서 진행하지 않는다.

## 자동 제안 타이밍
① 컨텍스트 압박(긴 세션) · ② "나중에/이어서" 발화 · ③ 태스크 경계 · ④ 산출물 완성 직후 · ⑤ **원격 세션에서 첫 개인 데이터가 생긴 직후**(모드 C 진입 여부를 그때 정한다 — 나중에 하면 이미 늦다).

## 성공 기준
- **A**: `.private/session-state.md` 최상단이 오늘 날짜 Latest 블록 · gitignore 확인 · 커밋 안 됨.
- **B**: `git show origin/main:docs/HANDOFF.md` 최상단이 오늘 날짜 · (CI green 또는 무CI) · 재개 명령 동작 · fallback 2개 이상.
- **C**: 저장소 private **실측 확인** · `.private/`가 추적됨(`git ls-files .private/ | head`) · 푸시 완료 ·
  되돌릴 수 없음 고지가 `.gitignore`/README에 남음 · **`git clone` 한 번으로 재개 가능**함을 사용자에게 명시.

## 금지 (원본 안티패턴 + career 추가)
- ❌ `.private/`(PII)를 커밋/main 머지 — **D-6 위반**. *단 모드 C(저장소 private 실측 확인 + 사용자 명시 동의)는 예외이며, 그때도 되돌릴 수 없음을 반드시 고지한다.*
- ❌ **저장소가 private이라는 사용자 말만 믿고** 개인정보 커밋 — 반드시 실측 확인.
- ❌ 원격·임시 컨테이너에서 **모드 C를 제안조차 하지 않아** 사용자가 매 세션 재입력하게 만들기.
- ❌ 잃으면 안 되는 사실을 **대화에만** 두고 파일화하지 않기(컨텍스트 관리 ①).
- ❌ `/tmp`·`/root` 등 임시 경로에 핸드오프 저장.
- ❌ 개인 세션 상태를 `docs/HANDOFF.md`(공개)에 기록.
- ❌ 업데이트만 하고 저장/영속 처리 안 함.

## 완료 보고 (선택)
길거나 산출물이 많은 세션은 자체완결 HTML 완료 보고서(report.html 표준: 심플 요약 + `<details>` 상세)로 마무리 가능.
